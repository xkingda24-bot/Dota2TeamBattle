## 二、数据口径（重要，后续改统计时以此为准）

| 指标 | 口径 |
|---|---|
| 参赛 | **真正进过队伍**的赛事数。只报名替补、未上场不计；报名总数单独放在 `registered` |
| 比赛场次 | `matches` 里每场已完成（`status='done'` 且有 `winner`）的 BO 记 1 场，不看比分 |
| 胜负 | 该场 winner 是否是自己所在队伍 |
| 名次 | 直接复用 `standings.calculateStandings`，**不另写一套推断**；总决赛未出结果的赛事不出名次 |
| 冠 / 亚 / 季 | 名次为 1 / 2 / 3 的赛事数 |
| 最佳搭档 | 同队同场累计：搭档同场次数、共同胜场、胜率；最多返回 5 人 |
| 连胜 | 按赛事 `createdAt` 正序、场内按赛程顺序跨赛事累计；`bestStreak` 历史最佳，`currentStreak` 当前连续 |
| 队长次数 | 自己在队伍里是队长（`teams[].captain`）的赛事数 |

⚠️ **队伍标识反查**：生成对阵时队伍会按落位表重排，对阵文档里记的是落位号 `T{n}`，不是队伍下标。统计时必须用 `seeding.indexOf(队伍下标)` 反查（`player-stats.js` 的 `teamSlotOf`）。这条已由 `player-stats.test.js` 的「落位反序」用例锁定——写错会出现「别人的胜负算到自己头上」。

## 三、后端改动

### 3.1 新增动作 `getPlayerProfile`（第 49 个动作）

- 只读、公开：不传 `openid` 看自己，传了看他人；**不返回任何管理信息**，只返回名片公开字段与统计结果
- 赛事读取：主路径 `where({ registeredOpenids: openid })`（报名时由 `buildRegistrationSummary` 写入的数组），分页最多 300 条；再补一次 `registrations.openid` 嵌套查询兜底旧赛事，失败忽略
- 字段投影只取赛程/队伍相关字段，不拉感言、暗号等无关内容
- 搭档昵称批量补查，避免档案页出现空白名字

### 3.2 新增模块

| 文件 | 说明 |
|---|---|
| `bracket-resolve.js` | 从 `tournaments.js` 抽出的纯函数 `resolveBracket`，赛事详情与生涯统计共用（`tournaments.js` 仍原样导出，调用方无感） |
| `player-stats.js` | 纯函数 `buildPlayerStats(tournaments, openid, { nameByOpenid })`，不访问数据库，可直接单测 |

### 3.3 未做的事（有意为之）

- **没有建 `playerStats` 增量汇总表**：当前按玩家查询其参与赛事即可，量级到几百场仍可接受；等赛事总量明显变大再切换成归档时增量写入，接口形状不变
- 没有引入 ELO 实力分：赛季积分保持唯一口径，避免玩家分不清「哪个代表我强」

## 四、战报长图

- `utils/poster.js` 纯绘制模块，设计尺寸 750 × 1200，导出同尺寸 PNG
- `pages/poster` 负责取数、挂 canvas 2d、导出、保存/分享：
  - 保存：`wx.saveImageToPhotosAlbum`，拒绝授权时弹「去设置」引导 `wx.openSetting`
  - 分享：`wx.showShareImageMenu` 直接把图片发到聊天（基础库 2.14.3+，当前 3.17.4 满足）；低版本降级为预览 + 长按转发
  - 点画布可放大预览
- 两套模板：
  - **赛事战报**：赛事名 / 赛制 / 队伍数 / 时间 → 冠军队伍与成员 → 最终名次（最多 6 行）→ 最长的一条赛后感言
  - **生涯战报**：昵称与天梯/位次/签名 → 参赛 / 胜率 / 冠军三块数据 + 冠亚季 → 本赛季积分 → 最佳搭档（3 人）→ 最近战绩（3 场）
- 数据为空时不会崩：总决赛没打完会显示「结算后出现在这里」，无感言则不画感言块

## 五、报名进度分享卡

`utils/share-text.js` 纯函数，标题规则按优先级：

| 情况 | 转发标题 |
|---|---|
| 队长没满 | 「XX · 还差 N 位队长开车」 |
| 队员没满 | 「XX · 8 队局还差 N 人」 |
| 人齐但有替补位 | 「XX · 人已齐，替补还有 N 个位置」 |
| 全满 | 「XX · 人已齐，来看阵容」 |
| 已进选人 / 对战 / 结算 | 「选人中，来看阵容」「正在对战，来看赛程」「已结算，来看最终名次」 |

- 报名页 `onShareAppMessage` 改用该文案；落地路径仍是 `/pages/register/register?id=xxx`，**不带暗号**（转发不等于泄露暗号）
- 分享入口为右上角「…」→ 转发（曾做过「邀请好友」按钮，因观感不佳已移除）
- 缺口计算基于服务端返回的 `captainFilled / playerFilled / waitlistFilled / N / K / waitLimit`，系统分组模式没有队长名额

## 八、已知边界

- 极旧赛事若既没有 `registeredOpenids`、`registrations.openid` 嵌套查询也不可用，生涯统计会漏掉这些赛事；跑一次历史回填（归档流程会顺带补 `registeredOpenids`）即可修复
- 生涯数据不做缓存，每次进页面实时算；单玩家赛事数很大时可加 60s 前端缓存
- 赛季维度的「年度报告」目前以生涯战报代替，赛季单独报告（含赛季内名次分布）留待下一步
